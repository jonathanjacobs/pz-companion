# Contributing

Contributions should be small, reviewable, documented, and compatible with the project's clean-room policy.

## Expectations

- Do not submit copied or insufficiently licensed code/assets.
- Preserve clear provenance for third-party dependencies and model weights.
- Add comments for non-obvious logic, state transitions, loops, and failure handling.
- Keep language-model output behind validation boundaries; never execute generated code.
- Prefer deterministic, testable game logic over opaque behavior.
- Update `CHANGELOG.md` for user-visible or architectural changes.
- Use descriptive commits and pull requests.

## Licensing

Unless explicitly marked otherwise, contributions to the software codebase are submitted under Apache-2.0.
